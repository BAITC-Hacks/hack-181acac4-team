# HackAlem AI

Мини-сервис для оформления бизнес-задач, прозрачного рейтинга и откликов студенческих команд. Общий контракт и владельцы файлов описаны в [AGENTS.md](AGENTS.md).

## Запуск

1. Если нужен OpenAI, скопируйте `.env.example` в `.env` и впишите `OPENAI_API_KEY`. Не добавляйте `.env` в Git.
2. Запустите `docker compose up --build` из корня репозитория.
3. Откройте интерфейс: <http://localhost:5173>. API: <http://localhost:8000/docs>. Проверка базы и API: <http://localhost:8000/api/health>.

Конструктор ANU-6: описание → три вопроса → ответы → редактирование всех полей → ручное подтверждение → публикация. Рейтинг, каталог и отклики добавляются отдельными задачами ANU-7–ANU-10.

## Проверка конструктора

Во вкладке «Бизнесу» введите «Нужен бот для кофейни», ответьте на три вопроса, отредактируйте карточку и отметьте подтверждение. Кнопка публикации доступна только после подтверждения; сервер также проверяет этот переход. Сохранённая правка отменяет подтверждение и снимает прежнюю публикацию. Сохранённая задача восстанавливается после перезагрузки на том же браузере.

Для OpenAI заполните `OPENAI_API_KEY` и `OPENAI_MODEL` в корневом `.env`, затем пересоздайте backend: `docker compose up -d --force-recreate backend`. Ключ не передаётся frontend. Используются Structured Outputs, ограничение времени запроса и проверка цитат по исходному описанию/ответам. Промпт, форматы AI-ответов и локальная заглушка находятся в `backend/app/ai/client.py`. Неизвестные поля остаются пустыми; финальную достоверность проверяет бизнес.

При недоступности API можно повторить действие или включить на экране «Деморежим без OpenAI». Это явная локальная заглушка: она копирует описание в контекст и спрашивает о пользователях, данных и успехе. Ответы переносятся дословно в соответствующие поля; «не знаю» оставляет поле пустым. Для API тот же режим включается параметром `?mode=demo` при создании черновика и отправке ответов. Заглушка не имитирует полноценный анализ.

Проверки: из `backend` выполните `python -m unittest discover -s tests -v`; из `frontend` — `npm run build`. Backend-проверки используют отдельную SQLite-базу в памяти и имитацию ошибок OpenAI. Реальный PostgreSQL и OpenAI проверяются отдельно через Compose. Пока ANU-7 не подключён, подтверждение возвращает `score: null`, без выдуманных баллов.

## Структура

- `backend/app/models.py` — таблицы PostgreSQL; `schemas.py` — JSON-контракт API.
- `backend/app/drafts.py`, `cards.py`, `catalog.py`, `proposals.py` — тонкие маршруты FastAPI.
- `backend/app/services/` — бизнес-правила по модулям; `backend/app/ai/` — доступ к OpenAI.
- `frontend/src/types.ts` — типы API; `frontend/src/features/` — экраны по модулям.

Каждый агент берёт задачи только своего владельца в Linear и работает в ветке с номером задачи. После обновления `main` Kojizz заполняет `services/scoring.py`, `seed.py` и свой frontend-модуль; Aslan — каталог, отклики и свои frontend-модули. Anuar подключает готовые модули и проверяет полный сценарий.
